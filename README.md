# 会员订阅

一个本地优先的会员订阅管理工具：记录会员、实际支付、到期日和续费成本，对比不同平台的报价，也支持多人联合购买后的费用分摊。

数据保存在本机 SQLite 中，不需要注册账号，也不依赖云服务。适合个人整理各类会员、订阅和长期服务的实际支出。

既可以按 Web 方式在浏览器中使用，也可以打包成 Windows 桌面应用；桌面版双击即可打开，关闭后数据仍会保留在本机。

## 下载

Windows 桌面版（当前版本 `0.1.0`）发布在 [GitHub Releases](https://github.com/luopeijun/member-subscription/releases/latest)：

- `会员订阅-0.1.0-setup.exe`：安装版，可选择安装目录并创建快捷方式
- `会员订阅-0.1.0-portable.exe`：便携版，双击直接运行

安装包没有代码签名，Windows 可能提示“未知发布者”，选择“仍要运行”即可。首次启动时可以把旧的 `data/app.db` 导入桌面版，旧数据不会被删除。

## 功能总览

| 页面 | 能做什么 |
| --- | --- |
| 总览 | 查看月均 / 年均支出、分类月均环形图、会员月均 Top 6、近 12 个月实际 / 未来支出、90 天内到期提醒 |
| 会员 | 管理会员与套餐、筛选状态和类别、搜索、记录购买或续费 |
| 联合续费 | 一次购买多个会员，分别设置时长，按天数分摊费用，并同时顺延各自到期日 |
| 流水 | 查看和筛选每一次实际支付；联合续费按整条购买记录分组展示 |
| 比价 | 记录平台报价，对比等效月成本；支持整条联合报价和费用分摊 |

## 功能明细

### 总览

- 月均订阅支出、年均支出、活跃会员数、累计支出
- 30 天内到期数量、已过期数量
- 未来 90 天续费提醒，可直接进入续费记录
- 分类月均环形图，展示活跃会员的成本构成；悬停可查看类目月均、占比和会员数
- 会员月均支出 Top 6，快速看出钱主要花在哪些会员；悬停可查看套餐、月均和占比
- 近 12 个月实际支出与未来 12 个月预计续费可切换查看；悬停柱状图可查看月份和金额，预计部分按下次续费日和计费周期估算，仅统计活跃会员

### 会员

- 服务、套餐、类别、计费周期、标价、购买平台、账号、开始日期、备注
- 状态：`活跃`、`想买`、`已过期`
- 按状态、类别筛选，按服务名、平台或备注搜索
- 会员列表固定每页 9 条，使用分页器翻页
- 「想买」只用于建档，不计入支出、到期提醒和统计
- 为「想买」的会员记录一笔购买后，会自动转为「活跃」
- 记录续费时可填写本次支付覆盖的天数，也可以直接填写下次续费日，两者会互相换算
- 手填的「下次续费日」优先于系统按计费周期推算的日期
- 比价页会在单个会员的「我的购买」下方显示其关联的「联合报价」参考块，用分摊后等效月成本与当前月均对比
- 联合报价按分摊后差额从省到贵排序，默认显示最省的一条；多条时可展开查看，并标注同捆套餐

支持以下计费周期：

`1 天`、`1 周`、`月付`、`季付`、`半年付`、`年付`、`2 年`、`一次性付费`、`买断（永久）`

### 联合续费

适合一次购买多个会员、但每个会员拿到的时长不同的情况。

- 至少选择两个会员
- 每个会员可以单独设置获得的天数，也可以使用快捷时长批量应用
- 填写本次购买总金额和支付日期
- 费用归属支持两种方式：
  - **均分（按天数）**：按每个会员实际获得的天数分摊
  - **主会员承担**：全部金额记在主会员名下
- 均分时按分向下取整，除不尽的余数记在主会员
- 一次联合续费会生成一条购买记录和多笔支付，并分别顺延每个会员的到期日
- 会员之间始终独立，联合购买不会把会员合并

添加会员时可以直接在输入框中输入名称搜索，候选列表约显示 10 条后滚动。

### 流水

流水页只用于查看和筛选，不在这里新增支付；新增支付从会员卡片的「记一笔购买 / 记一笔续费」进入。

- 按会员名称或套餐名称搜索
- 支付日期支持只填开始日期、只填结束日期，或同时填写起止日期
- 普通续费与联合续费分 Tab 查看，各自拥有独立的分页器和每页条数
- 展示当前 Tab 和筛选范围内的记录数、合计金额与均值
- 联合续费按整条购买记录分组展示，不能单独删除其中的某一笔支付
- 删除支付会重新计算成本统计，但不会主动修改手填的「下次续费日」

### 比价

- 联合报价与会员分 Tab 查看，各自拥有独立的分页器
- 联合报价每页 10 条，会员每页 10 个会员
- 不再单独展示「全部报价记录」，平台报价直接在对应套餐内查看和管理

#### 平台报价

- 每个套餐可以记录多个平台、多个时间点的报价
- 报价包含价格、平台、记录日期、备注
- 可以填写套餐实际包含的总天数；不填写时按套餐自身的计费周期折算
- 按等效月成本与当前购买价格比较，显示贵 / 便宜 / 持平
- 首次记录某个套餐时，会同时创建套餐；后续可在同一套餐下继续追加报价
- 平台报价支持在对应套餐行内编辑和删除；编辑时套餐固定，只能修改报价信息

#### 联合报价

- 一条联合报价包含多个会员和整条捆绑包的总价
- 每个会员单独填写获得天数
- 费用归属支持「均分（按天数）」和「主会员承担」
- 展示每个会员的分摊金额，以及分摊后的等效月成本
- 按相同服务时长计算当前组合成本，再与捆绑包总价对比
- 差额为正显示「贵」，为负显示「省」，相等显示「持平」
- 联合报价支持编辑；可以调整已有会员的时长，但不能添加或移除会员

### 数据管理

页面底部提供：

1. **导入数据**
2. **导出数据**
3. **清空全部数据**

导入采用追加方式，不会覆盖已有记录。服务和套餐会按名称、周期匹配后复用或新建；会员、支付、联合续费、报价等记录会追加导入。兼容旧版备份中的历史字段。

清空全部数据需要二次确认，并会先在当前数据目录的 `backups` 中自动生成一份数据库快照。该操作不可撤销，建议同时使用「导出数据」自行保留一份 JSON。

## 核心规则

### 金额

- 所有金额使用人民币
- 数据库以「分」存储整数，界面显示为元
- 月均成本四舍五入到分

### 时长与月成本

- 联合续费、联合报价和支付覆盖时长统一使用「天」
- 一个月按 `365 / 12` 天折算，因此 365 天正好等于 12 个月
- 单次可录入时长为 1 到 3650 天
- 月成本 = 金额 × `365 / 12` ÷ 覆盖天数
- 平台报价未填写总天数时，按套餐计费周期折算

### 状态与下次续费日

- 「想买」没有到期日，也不计入统计
- 活跃 / 已过期状态由「下次续费日」和今天自动判断
- 下次续费日优先使用手动填写的日期
- 未手动填写时，按最近一笔支付日期 + 本次覆盖时长 / 套餐计费周期推算
- 没有支付记录时，按开始日期推算
- 删除支付会重新计算成本统计；手填的下次续费日不会被主动修改
- 未手填下次续费日时，删除支付或联合续费后，日期会按剩余支付重新推算

### 联合费用归属

- 均分：`floor(总金额 × 该会员天数 ÷ 所有会员总天数)`，余数记在主会员
- 主会员承担：全部金额记在主会员
- 分摊结果在读取时计算，不额外存储冗余金额
- 联合报价和联合续费使用同一套费用归属规则

## 技术栈

- 前端：Vite + React 18 + TypeScript
- 后端：Express
- 数据库：SQLite（better-sqlite3，WAL 模式）
- 样式：SCSS
- 图表：Recharts（分类环形图、会员 Top 6、月度支出图）
- 测试：Vitest（金额、日期、周期、续费预测和报价等工具函数）
- 桌面端：Electron + electron-builder，使用 esbuild 打包主进程和本地服务
- 开发模式下 Vite 以中间件方式运行在 Express 中，前后端同端口

## 快速开始

要求：Node.js 20+、npm。

```bash

npm run dev
```

打开 <http://localhost:5173>。

```bash
npm run build

```

可以通过环境变量修改端口和监听地址：

```bash
PORT=8080 HOST=0.0.0.0 npm start
```

## Windows 桌面版

桌面版会把前端、Express 服务和 SQLite 一起放进 Electron 应用中，启动后直接打开应用窗口，不需要浏览器或终端。

构建并本地运行：

```bash
npm run desktop
```

生成安装包和便携版：

```bash
npm run desktop:pack
```

产物位于 `release/`：

- `会员订阅-0.1.0-setup.exe`：安装版，可选择安装目录并创建快捷方式
- `会员订阅-0.1.0-portable.exe`：便携版，双击直接运行

安装版和便携版都不需要预先安装 Node.js。

桌面版数据保存在：

```text
%APPDATA%\会员订阅\data\app.db
```

清空数据前的自动快照位于 `%APPDATA%\会员订阅\data\backups\`。应用菜单「文件 → 打开数据目录」可以直接打开该文件夹。

首次启动时，如果当前工作目录或 EXE 所在目录存在旧的 `data/app.db`，应用会提示是否把旧数据复制到桌面版；没有自动检测到时，也可以在欢迎弹窗中选择旧数据库文件，或从零开始。旧数据不会被删除。也可以先在网页版「导出数据」，再在桌面版「导入数据」。

构建说明：

- `npm run desktop:pack` 会临时把 `better-sqlite3` 切换为 Electron ABI 的预编译模块，打包完成后自动恢复 Node.js 版本。
- 如果构建或运行被强制中断，可执行 `npm run desktop:restore` 恢复 Node.js 原生模块，避免影响 `npm test`。
- Electron 33 使用 Node 20 ABI，已匹配 `better-sqlite3` 的 `electron-v130-win32-x64` 预编译包。

## API 概览

开发模式下 API 位于 `/api`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/state` | 获取完整应用状态 |
| `POST` | `/api/subscriptions` | 新增会员 |
| `PUT` | `/api/subscriptions/:id` | 修改会员 |
| `DELETE` | `/api/subscriptions/:id` | 删除会员 |
| `POST` | `/api/subscriptions/:id/payments` | 记录购买 / 续费 |
| `DELETE` | `/api/payments/:id` | 删除单笔支付 |
| `POST` | `/api/joint-renewals` | 记录联合续费 |
| `DELETE` | `/api/joint-renewals/:id` | 删除联合续费 |
| `POST` | `/api/plans` | 新增套餐，可同时记录首条平台报价 |
| `DELETE` | `/api/plans/:id` | 删除套餐 |
| `POST` | `/api/snapshots` | 追加平台报价 |
| `PUT` | `/api/snapshots/:id` | 修改平台报价 |
| `DELETE` | `/api/snapshots/:id` | 删除平台报价 |
| `POST` | `/api/joint-quotes` | 记录联合报价 |
| `PUT` | `/api/joint-quotes/:id` | 修改联合报价（可调时长，不可增删会员） |
| `DELETE` | `/api/joint-quotes/:id` | 删除联合报价 |
| `GET` | `/api/export/json` | 导出全部数据 |
| `POST` | `/api/import/json` | 追加导入数据 |
| `DELETE` | `/api/data` | 清空全部数据，需要确认参数 |
| `POST` | `/api/seed` | 载入示例数据 |
